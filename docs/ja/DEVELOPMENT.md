# vivivi: 開発者ガイド (DEVELOPMENT)

本書は、`vivivi` のローカル開発環境のセットアップ、ワークスペースビルド、実行コマンド、ビルドプロファイルの最適化仕様、およびコード品質検証手順について説明します。

---

## 1. 開発環境のセットアップ

### 前提条件
- **Rust ツールチェーン**: Rust 1.80 以上 (最新 stable 推奨、Edition 2024 対応)
- **Git**: バージョン管理

```powershell
# ツールチェーンの確認
rustc --version
cargo --version
```

### リポジトリのクローン
```powershell
git clone https://github.com/tkshnkgwr/vivivi.git
cd vivivi
```

---

## 2. コマンドクイックリファレンス（チートシート）

用途に応じた実行・ビルドコマンドのまとめです。設定ファイルを書き換える必要はなく、コマンドの引数（`--release` 等）で全自動で切り替わります。

### 2.1 GUI版（vivivi-gui）の実行

| 用途                                    | 実行コマンド                               | 特徴・動作速度                                                        |
| :-------------------------------------- | :----------------------------------------- | :-------------------------------------------------------------------- |
| **日常の開発・デバッグ**                | `cargo run -p vivivi-gui`                  | 自前コードは数秒でビルド完了。外部GUIライブラリはキャッシュで超軽快。 |
| **ファイルを開いて起動**                | `cargo run -p vivivi-gui -- <ファイルパス>`| 指定ファイル（エンコーディング・改行コード自動判別）を初期表示。      |
| **最高速度での動作確認（リリース）**    | `cargo run -p vivivi-gui --release`        | 全体を極限最適化（LTO・SIMD・デバッグ情報除去）して最高速起動。       |
| **配布用バイナリのビルド**              | `cargo build -p vivivi-gui --release`      | `target/release/vivivi-gui.exe` に単一実行ファイルを出力。            |

### 2.2 TUI版（vivivi）の実行

| 用途                                    | 実行コマンド                               | 特徴・動作速度                                                        |
| :-------------------------------------- | :----------------------------------------- | :-------------------------------------------------------------------- |
| **日常の開発・デバッグ**                | `cargo run` または `cargo run -p vivivi`   | ターミナル（Crossterm / Ratatui）上でTUIエディタを起動。              |
| **最高速度・配布用ビルド**              | `cargo build --release`                    | `target/release/vivivi.exe` に単一実行ファイルを出力。                |

## 3. ビルドプロファイル最適化アーキテクチャ

RustのGUI開発（egui / eframe）において、「開発中のビルド待ち時間（コンパイル速度）」と「GUIのスムーズな描画性能（実行速度）」を両立させるため、ルート `Cargo.toml` で**ハイブリッド最適化プロファイル**を採用しています。

### 3.1 プロファイル設定一覧

```toml
# --- ビルドプロファイル最適化設定 ---

# ① 開発・デバッグ実行時でも、外部依存クレート（egui, wgpu, glow等）をフル最適化
[profile.dev.package."*"]
opt-level = 3

# ② 自前コードの開発ビルドは軽量最適化でコンパイル時間を短縮
[profile.dev]
opt-level = 1

# ③ 配布・リリースビルド専用の最高速化設定
[profile.release]
opt-level = 3
lto = "thin"
codegen-units = 1
strip = true
```

### 3.2 各オプションの役割と技術的解説

| オプション設定                   | 対象スコープ         | 技術的役割と効果                                                                                  |
| :------------------------------- | :------------------- | :------------------------------------------------------------------------------------------------ |
| `[profile.dev.package."*"] = 3`  | 外部依存クレート全体 | egui/epaint/wgpuの頂点生成・SIMD計算・フォントラスタライズをフル最適化。高CPU負荷・カクつきを根絶。|
| `[profile.dev] = 1`              | 自前クレート         | 自前コードのインライン展開や最小限の最適化を適用しつつ、1〜3秒の爆速インクリメンタルビルドを維持。 |
| `[profile.release] = 3`          | プロジェクト全域     | 全関数を極限までインライン化・ループアンロール・SIMDベクトル化して最高速バイナリを生成。          |
| `lto = "thin"`                   | リリースリンク時     | ThinLTO（リンク時最適化）により、クレート境界を越えたデッドコード削除と関数インライン化を実施。   |
| `codegen-units = 1`              | リリースコンパイル   | 並列コード生成を1つに集約し、LLVMがプログラム全体を見渡して極限までバイナリサイズと効率を圧縮。  |
| `strip = true`                   | リリースバイナリ     | シンボルテーブルとデバッグ情報を実行ファイルから完全除去し、exeファイルのサイズを大幅に削減。    |

### 3.3 なぜ初回だけ時間がかかり、以後はサクサクなのか？
- **初回ビルド時**: 依存している外部クレート（数十個）の最適化（LLVMによる数学的パズル計算）が一斉に走るため、初回のみ数分間かかります。
- **2回目以降（日常開発）**: 外部クレートのコードは変更されないため、**一度作成された最適化成果物（キャッシュ）が100%再利用されます**。自分のコードを修正して `cargo run` する際は、数秒で差分ビルドが完了します。

## 4. テスト & 品質検証

コード変更時は以下の手順で品質検証を行います。全項目が警告ゼロでパスすることを担保してください。

```powershell
# 1. 型チェック・依存関係検証
cargo check --all-targets

# 2. 全クレートの単体・統合テスト実行
cargo test --all-targets

# 3. ドキュメントテスト（Doc-test）実行
cargo test --doc

# 4. Clippy 静的リント解析（警告ゼロを担保）
cargo clippy --all-targets -- -D warnings

# 5. フォーマット検証（不適合時は cargo fmt で整形）
cargo fmt --check
```
