# Rustdoc 生成ルール

Rust プロジェクト（vivivi）において Rustdoc（`///` または `//!`）を記述する際は、以下のルールを厳格に遵守すること。

## 1. 記述方針
- **言語**: 説明文およびコード内コメントは自然な日本語で記述すること。
- **セクション見出し**: 標準慣例（`# Panics`, `# Errors`, `# Examples`）を使用すること。
- **自明な説明の禁止**:
  - 関数のシグネチャをそのまま言い換えただけ（例:「IDを受け取りユーザーを返す」）の記述は禁止する。
  - 「どのような前提条件・制約があるか」「どのような副作用があるか」を重視して記述すること。

## 2. 構成テンプレート
公開（`pub`）関数・型・トレイトには、以下のセクションを必ず検討して含めること：

1. **1行の概要**:
   - 関数の目的や役割を端的に日本語で説明する。
2. **詳細説明**:
   - 必要に応じて仕様の背景、前提条件、関連する型へのリンク（[`Type`]）を記述する。
3. **# Errors**:
   - `Result` を返す場合、発生しうるエラーの条件や種類を網羅して記述する。
4. **# Panics**:
   - パニック（`panic!`）を引き起こす入力や条件が存在する場合、必ず明記する。
   - パニックしない場合は「パニックは発生しない」と明記するか、セクション自体を省略する。
5. **# Examples**:
   - 呼び出し側がそのまま利用できる最小限のコード例を提示する。
   - `cargo test --doc` で通る構文にすること。
   - 実行不可能な例（モックや実環境が必要なもの）には ```rust,no_run や ```rust,ignore を付与すること。
